# PRD — PDF Slide Extractor

## 1. 배경

강의 콘텐츠 제작자가 기존 PDF 교안을 **데이터 재처리(RAG·파인튜닝·검색 인덱스·재요약)** 용도로 변환하려고 할 때, 다음 작업이 반복적으로 필요합니다:

1. PDF의 슬라이드별 텍스트 + 시각자료(다이어그램·표·박스·화살표)를 **종합해서 자급자족 마크다운으로** 재구성
2. 시각적 보조가 필요한 페이지의 핵심 영역을 이미지 파일로 추출 (선택)
3. 마크다운 안에서 이미지 참조 연결

**핵심**: 출력 마크다운은 이미지 없이 텍스트만 읽어도 슬라이드 학습 내용이 완결되어야 합니다. 단순 OCR/텍스트 추출이 아니라 다이어그램의 의미·박스 간 관계까지 텍스트로 풀어쓴 결과를 원합니다.

이 작업을 손으로 하면 50페이지 PDF 한 권에 4~6시간 걸립니다. 본 도구는 이걸 5분 이내로 줄입니다.

## 2. 사용자

- **주 사용자**: 강의 콘텐츠 제작자 (개인 1명 또는 사내 소규모 팀)
- **기술 수준**: 비개발자도 사용 가능 (PDF 업로드 + 다운로드 클릭)
- **사용 빈도**: 주 1~5회 정도

## 3. 사용 시나리오 (User Journey)

### S1. 정상 흐름

```
[1] 사용자가 웹 페이지 접속
[2] PDF 파일 드래그&드롭 (또는 클릭해서 선택)
[3] "추출 시작" 버튼 클릭
[4] 진행률 표시 (예: "12/28 페이지 분석 중...")
[5] 완료되면 "다운로드" 버튼 활성화
[6] ZIP 파일 다운로드 → 압축 해제 → markdown 에디터로 열기
```

### S2. 결과 미리보기 (선택사항)

다운로드 전에 결과를 미리 볼 수 있어야 함:
- 슬라이드별 카드 형태로 마크다운 + 추출된 이미지를 표시
- "이 슬라이드는 마음에 안 듦" 표시는 v1에서는 없음 (v2 검토)

### S3. 오류 흐름

- **PDF가 아닌 파일** → 업로드 단계에서 거부, 에러 메시지
- **너무 큰 PDF (>100MB 또는 >100페이지)** → 거부 + 안내
- **스캔 PDF (텍스트 없음)** → 처리는 시도하되, 결과 품질 경고
- **LLM API 실패** → 해당 페이지 스킵, 사유 명시, 나머지는 계속
- **전체 작업 실패** → 에러 화면 + 재시도 버튼

## 4. 기능 요구사항

### 4.1 필수 (v1 MVP)

| ID | 기능 | 설명 |
|---|---|---|
| F1 | PDF 업로드 | 드래그&드롭 또는 파일 선택, 최대 100MB |
| F2 | 페이지 분류 | LLM이 각 페이지를 "본문" / "표지·구분 슬라이드" / "장식뿐인 페이지"로 분류 |
| F3 | **시각자료 종합 마크다운** | LLM Vision이 페이지 이미지 + 추출 텍스트를 함께 보고, 다이어그램·박스·표·화살표의 의미까지 풀어쓴 자급자족 마크다운 생성 |
| F4 | 보조 이미지 영역 결정 | 시각적 참조가 가치 있는 경우에만 LLM이 bbox 좌표 반환 (단순 비교 박스 등은 생략) |
| F5 | 이미지 크롭 | 결정된 영역을 PNG로 크롭, 파일명은 `{페이지번호}_{슬러그}.png` |
| F6 | ZIP 패키징 | content.md + images/ 폴더를 하나의 ZIP으로 |
| F7 | 진행률 표시 | 페이지 단위로 진행률 (`현재페이지/전체페이지`) |
| F8 | 다운로드 | ZIP 파일 다운로드 |

### 4.2 후순위 (v2 이후)

- 결과 미리보기 (슬라이드별 카드)
- 잘라낸 영역 수동 조정 (드래그로 bbox 편집)
- OCR 폴백 (스캔 PDF 지원)
- 다국어 (영어 슬라이드 PDF 지원)
- 작업 히스토리 (최근 추출 결과 다시 다운로드)
- 일괄 처리 (여러 PDF 동시)

## 5. 비기능 요구사항

| 항목 | 목표 |
|---|---|
| 처리 시간 | 30페이지 PDF 기준 ≤ 5분 |
| 페이지당 LLM 비용 | ≤ $0.05 (Claude Sonnet 4.5 Vision, 종합 재처리 기준) |
| 최대 PDF 크기 | 100MB / 100페이지 |
| 동시 처리 | 1건 (큐에 줄 서기) |
| 결과 보존 기간 | 1시간 후 자동 삭제 |
| UI 반응 시간 | 폴링 응답 ≤ 200ms |

## 6. 페이지 분류 기준

LLM이 각 페이지를 다음 중 하나로 분류합니다:

| 분류 | 정의 | 처리 |
|---|---|---|
| `content` | 본문 슬라이드. 학습 내용이 텍스트·다이어그램·표·코드 등으로 표현됨 | 텍스트 추출 + 이미지 영역 결정 |
| `section_divider` | 섹션 구분 페이지 ("학습 마무리", "오늘의 학습 알아보기" 등 큰 글씨만) | 마크다운에 H2 제목만 남기고 이미지 추출 안 함 |
| `cover` | 표지·종료 페이지 | 스킵 (마크다운에도 안 들어감) |
| `decorative_only` | 장식 일러스트만 있고 학습 내용 없음 (예: "실습 영상 확인" + 일러스트) | 텍스트만 추출, 이미지 추출 안 함 |

이 분류 결정은 LLM에 위임합니다. 자세한 프롬프트는 [LLM_PROMPTS.md](LLM_PROMPTS.md) 참조.

## 7. 보조 이미지 추출 기준

이 도구의 출력 마크다운은 **자급자족적**이므로, 이미지는 시각적 보조 참조용입니다. LLM이 다음 기준으로 첨부 여부를 결정합니다:

**첨부 (image_region 반환)**:
- UI 화면 캡처, 코드 캡처: 시각 정보가 본질
- 복잡한 플로우차트·아키텍처 다이어그램: 텍스트로 풀어도 시각적 배치가 더 명확함
- 데이터 시각화(차트·그래프): 트렌드를 한눈에 봐야 할 때

**미첨부 (null)**:
- 단순 비교 박스 두 개 (텍스트 풀이로 충분)
- 정의 박스, 라벨 박스 (마크다운 헤딩/리스트로 대체)
- 장식 일러스트만 있는 경우

**bbox 단위**:
- 페이지를 0~1000 정규화 좌표
- 헤더(슬라이드 제목 영역)와 푸터(로고)는 제외
- 한 페이지에 여러 시각자료가 흩어져 있으면 모두 포함하는 큰 bbox 1개

**제외 대상** (절대 결과 이미지에 포함되면 안 됨):
- 회사 로고, 헤더 아이콘(말풍선 등), 푸터, 페이지 번호
- 슬라이드와 무관한 장식 일러스트(아바타·잎사귀)

## 8. 성공 기준

- 딥코 KDC 18회차 PDF 기준, 28페이지 중 정확히 14페이지가 `content`로 분류됨 (이미 검증된 골든 데이터)
- **자급자족성**: content.md에서 모든 슬라이드의 다이어그램·표·박스 내용이 텍스트로 등장 (이미지 없이도 학습 가능)
- **환각 0**: 마크다운에 슬라이드 원본에 없는 내용이 들어가지 않음
- 사용자가 결과 ZIP을 받아서 즉시 RAG 인덱스/파인튜닝 데이터로 사용 가능
- 처음 보는 PDF에서도 본문/장식 분류 정확도 ≥ 90%
